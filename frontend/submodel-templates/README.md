# IDTA submodel templates & AAS metamodel

Vendored copies of the official Asset Administration Shell material, downloaded 2026-09-05.
Nothing here is written by this project — it is upstream content, kept verbatim so it can be
diffed against upstream and re-downloaded at any time with `./refresh.sh`.

All of it is published by the [IDTA](https://industrialdigitaltwin.org/) under **CC-BY-4.0**
(`LICENSE.txt` in each subfolder is the upstream copy).

| Source | What came from it |
| --- | --- |
| [`admin-shell-io/submodel-templates`](https://github.com/admin-shell-io/submodel-templates) (`main`) | `submodels/published/` — every published submodel template: spec PDF, AASX package, JSON template, and the AsciiDoc/PlantUML sources where upstream ships them |
| [`admin-shell-io/aas-specs-metamodel`](https://github.com/admin-shell-io/aas-specs-metamodel) (`master`) | `metamodel/schemas/` and `metamodel/documentation/` |
| [industrialdigitaltwin.org — AAS specifications](https://industrialdigitaltwin.org/en/content-hub/aasspecifications) | `metamodel/specifications/` — the six IDTA-0100x specification PDFs |
| [industrialdigitaltwin.org — submodels](https://industrialdigitaltwin.org/en/content-hub/submodels) | `submodels/idta-website/` — the 7 PDFs the website links that GitHub does not carry |

## Layout

```
submodel-templates/
├── README.md · refresh.sh · index.py · inventory.json
├── metamodel/
│   ├── specifications/     IDTA-01001 Part 1 Metamodel v3.2 (and Parts 2, 3a, 3b, 4, 5)
│   ├── schemas/            aas.json (JSON Schema) · AAS.xsd · rdf-ontology.ttl · shacl-schema.ttl
│   │                       + examples/ — 2 705 conformance instances per format (valid and invalid)
│   └── documentation/      IDTA-01001 AsciiDoc sources, figures and UML
└── submodels/
    ├── published/          54 template families, 161 template JSON files, 175 submodels
    └── idta-website/       superseded versions the IDTA site still links (see “Discrepancies”)
```

**177 MB in 9 126 files** (about 205 MB on disk — most files are tiny). The bulk of the *bytes* is
89 PDFs (97 MB), 152 AASX packages (25 MB) and 161 JSON templates (30 MB); the bulk of the *files*
is the metamodel's 8 115 conformance examples, which are three quarters of the count and 7 MB.

## Using it

- **`inventory.json`** is the index — the only derived file here, regenerated by `index.py`.
  One record per template file with its IDTA number, version, `idShort`, `semanticId`, element
  count and whether an AASX/PDF sits beside it. That is what a template picker needs; it saves
  opening 161 JSON files to find out that the current Nameplate is
  `https://admin-shell.io/idta/nameplate/3/0/Nameplate` with 42 elements.
- **`*.json`** template files are full AAS *Environment* documents
  (`assetAdministrationShells` / `submodels` / `conceptDescriptions`), so they can be POSTed
  to a repository or read with `@kaigara/shared-types` after unwrapping `submodels[]`.
- **`*.aasx`** are ZIP packages (OPC) containing the same content plus attachments — the
  realistic source of File/Blob payloads for attachment-heavy benchmarks.
- **`metamodel/schemas/json/aas.json`** is the schema to validate generated payloads against,
  which is what the proposal's correctness phase calls for; the `examples/` trees next to it are
  ready-made valid **and invalid** instances for the negative-test branch.

## Refreshing

```bash
./refresh.sh           # re-download everything from upstream, then rebuild the index
./refresh.sh --index   # only rebuild inventory.json from what is already here
```

`refresh.sh` re-scrapes the IDTA pages rather than using a pinned URL list, so a new spec
revision or a newly published template is picked up automatically. It replaces
`submodels/published/` and `metamodel/schemas|documentation/` wholesale — do not hand-edit them.

## Notes

**Not in git.** `.gitignore` excludes everything here except this README and the two scripts.
177 MB of third-party PDFs and binaries do not belong in the repository's history, and the repo
already treats reference material this way (`stress-forge/`, `basyx-setup/`, `docs/`). The scripts
are committed, so the folder is reproducible from a clean checkout. To vendor it after all, drop
the `frontend/submodel-templates/` block from `.gitignore`.

**If the Vite dev server feels slow**, the 8 115 schema examples are the reason. Either delete
them (`rm -rf metamodel/schemas/*/examples`, `refresh.sh` brings them back) or exclude the folder
from the watcher in `frontend/vite.config.ts`:

```ts
server: { watch: { ignored: ["**/submodel-templates/**"] } }
```

Nothing under `frontend/` outside `src/` and `public/` is bundled, so the production build is
unaffected either way.

## Discrepancies found while downloading

- **GitHub is ahead of the website** for several templates: it carries Digital Nameplate
  **3.0.1**, Technical Data **2.0.1** and Handover Documentation **2.0.1**, while the website's
  download links still point at 3.0 / 1.2 / 2.0. `published/` is therefore the authority here.
- **The website is ahead for the specifications**: Part 1 Metamodel is at **v3.2 (July 2026)** and
  Part 2 API at **v3.2**, whereas this repository's proposal cites IDTA-01001-3-0-2 and
  IDTA-01002-3-0, and `backend/src/timeline/aasOperations.ts` is written against v3.0/3.1
  endpoints. Worth a look before the next API change — the endpoints used today are unaffected.
- **One numbering mismatch**: the website publishes Wireless Communication as
  `IDTA-02024-1-0_…pdf`, GitHub as `IDTA 02022-1-0_…`. Both copies are kept.
- The 7 files in `submodels/idta-website/` are otherwise all *older* versions the site still
  links (Technical Data 1.2, Digital Nameplate 2.0, Control Component Type/Instance 1.0,
  Carbon Footprint 0.9, Maintenance Instructions 1.0). Kept for completeness, superseded in use.
- Every one of the 161 template JSON files parses and indexes cleanly — no upstream breakage.
